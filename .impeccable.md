## Design Context

### Users and use cases
This is a reusable starter for developers creating independent applications. Its neutral demo demonstrates sign-in, protected workspaces, records, settings and private files. The next product's users and domain are intentionally unspecified; establish them with its owner before building product-specific screens.

### Brand personality
Practical, clear and approachable. Preserve the shared foundation, readable hierarchy and calm interactions. Invariant supplies the shared neutral styling, precise motion and layered materials.

### Principles
- Rebrand through semantic tokens; keep status colors independent.
- One owner for typography, controls, overlays and surfaces; no feature-level forks.
- Forms preserve drafts, block duplicate actions and report truthful results.
- Mobile, keyboard, enlarged text, reduced motion and dark mode are first-class states.
- This template carries no Yardwork customers, artwork, credentials, production identifiers or domain backend.

### Approved demo and documentation direction
The owner explicitly requested the original Yardwork demo look and interactions, isolated in this personal repository and Cloudflare account. The audience is developers exploring and reusing this foundation. Preserve the Yardwork office screens and synthetic fixtures as a demo; provide an Invariant-inspired searchable showcase with live controls, usage code, and a practical how-to guide. Preserve the demo artwork and interaction flow; the later approved unified Invariant styling governs reusable controls.

### Unified Invariant styling system
The owner explicitly chose the Invariant styling system for every component. Use its neutral warm palette, rounded rectangular controls, layered hairline shadows, rem typography and precise spring/ease-out motion. packages/highway-styles/src/tokens.css is the single source; --inv-* names are compatibility aliases. Foundation supplies form, focus, pending and domain behavior; it is not a second visual collection. The Yardwork demo remains synthetic and independent.

Preserve the original Foundation glass surface as a reusable material within the Invariant system. Do not replace its wash, translucent fill, rim, inset highlight, blur or elevation with the flat Invariant card recipe.

### Approved application typography — October 21, 2026
Use the exact eight-role scale in `docs/PACKAGES.md`: default UI 14/20; dense tables 13/20; metadata 12/16; micro 11/16; card titles 16/24; sections 18/28; page titles 24/32; primary KPI 30/36. This supersedes the previous 15px body / 64px display scale. Font-family branding preserves these roles. Retain rem scaling and a 1rem minimum for editable phone inputs.

Analytics dashboards use tabular figures; only 400/500/600 weights; muted14px secondary labels; dense desktop tables13/20 with expandable40px rows; primary KPI30px and secondary KPI24px. Use the existing roles and package analytics helpers.
